# 子智能体并行优化说明

2026-10-24 更新。原代码备份：`backups/before-parallel-20261024-170353.zip`，仅包含本次涉及的源码及原回归测试，不包含密钥。

## 为什么移除锁

独立只读接口不需要互斥。原有 `delegation_lock` 和 `tool_lock` 将整个模型、接口等待过程串行化；现在移除两把锁。

共享状态仍需正确处理：预算检查和扣减在同一事件循环中同步完成，中间没有 `await`；证据按独立 `task_id` 存储；相同专家和相同任务的在途委派共享一个 Task，完成后复用缓存。各工具的数据库记录使用独立会话。

每个请求使用 Semaphore 限制同时运行的专家数，默认 3。它允许多个任务同时执行，作用是控制资源用量。可在 `.env` 设置 `MULTI_AGENT_PARALLEL_LIMIT=1` 至 `6`，修改后重启 AI 服务。此值是每个 Run 的上限，不是全服务并发上限。

主控开启 `parallel_tool_calls`，提示词要求独立任务同轮委派；专家内部仍按依赖执行。例如“查积分余额”和“查商品详情”可同时进行；需要先发现商品编号再做兑换预校验时必须分轮执行。是否同轮发出多个调用还取决于模型实际输出。

请求超时统一由根执行器控制。退出执行期限后，先取消并等待在途子任务完成清理，再返回结果；不会把子任务取消转成普通业务失败。清理可能使返回时间略超执行期限。

并行读取不保证积分、商品等跨接口数据来自同一个数据库快照；兑换预校验仍不等于最终下单或扣分。

## 验证

自动化测试覆盖独立委派与业务工具重叠、真实 LangGraph ToolNode 同轮并行、重复委派去重、并发上限、全局预算、证据隔离、根请求取消及主控失败后的异步清理。

最终执行 `.venv/Scripts/python.exe -m unittest discover -s tests -q`，102 项全部通过。代码复核发现并修复了“主控失败后，期限到达再次取消专家异步清理”的竞态，并用跨越执行期限的异步清理测试验证。

Terminal 日志新增每次模型调用的相对开始/结束时间与模型并发峰值。累计模型耗时是各次耗时相加，并行时可以大于请求实际总耗时。
