## Terminal 运行

从 AI 服务根目录执行：

```powershell
# 仅列出20题，不调用模型
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test_customer_scenarios.ps1 -List

# 执行全部20题，实际调用 .env 中的模型
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test_customer_scenarios.ps1

# 先只测余额、兑换和跨领域问题
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test_customer_scenarios.ps1 -Cases '01,05,20'
```

也可直接运行 Python：

```powershell
.\.venv\Scripts\python.exe -u scripts/test_customer_scenarios.py --cases 01,05,20
```

默认请求本机 AI `8002` 和 `.env` 中的 Ecommerce 地址，使用 `user_001` 演示身份。需要本地数据库、Ecommerce、AI 已启动，积分演示数据已初始化。可以通过 `--ai-url`、`--user-id` 切换调用目标与身份；20题中的固定订单主要属于 user_001。

## 日志与指标

每题开始即打印问题，等待期间每10秒打印进度。接口返回后展示：

- 总耗时：整次 AgentRun 的执行耗时。
- 模型调用次数、模型累计耗时，以及每次调用所属的主控/子智能体、模型名称、状态和耗时。
- 每次模型调用的相对开始/结束时间，以及模型并发峰值；时间区间重叠可证明实际并行。以首个模型调用开始为零点。
- 每次模型调用的输入、输出和总 Token，JSON 中保存于 `model_metrics.calls[].token_usage`；模型未返回用量或调用未完成时显示“Token 未知”。如供应商返回缓存读取、推理 Token 明细，JSON 一并保留；明细是输入/输出的组成部分，不能重复加总。
- 业务工具调用总数、成功数、累计耗时，以及每次调用所属的子智能体、工具名称、结果码和耗时。
- 输入/输出 Token 数量、智能体回复、未通过的检查项。

模型耗时通过 LangChain 调用回调测量，不使用减法估算。模型次数表示框架层调用次数，SDK 内部 HTTP 重试不单独计数。模型累计耗时是各次调用时间之和，有并行调用时不等于墙钟耗时。业务工具次数不包括主控的委派工具和结构化输出工具。

工具次数包含已发起的调用；超时取消且未记录完成时间时显示“未完成/耗时未记录”，工具累计耗时只累加已记录的数值。

HTTP 超时或失败时只记录客户端实际等待时间，服务端模型、工具及 Token 指标显示“未知”，不会猜测为0。

身份来自主控和专家实际执行时注入的 metadata；工具按 task_id 关联所属专家，不根据工具名猜测。日志标签示例：

```text
模型#1 [主控智能体/supervisor] z-ai/glm-5.3-flash SUCCESS ...s
模型#2 [商品子智能体/product] z-ai/glm-5.3-flash SUCCESS ...s
模型#3 [积分子智能体/points] z-ai/glm-5.3-flash SUCCESS ...s
工具#1 [商品子智能体/product] get_product 成功 ...s code=OK
工具#2 [积分子智能体/points] check_points_eligibility 成功 ...s code=OK
```

上例仅展示格式，实际调用顺序、次数及耗时以运行输出为准。JSON 同步保存 agent_code、agent_role、agent_name、task_id，便于追踪。

PowerShell 入口同时在 `reports/` 保存 `.log` 文本和 `.json` 报告。Python 入口逐题保存 JSON，可用 `--output` 指定路径。报告不保存 API Key、JWT 或内部令牌。真实模型运行产生 Token 消耗，自动化单元测试不调用真实模型。

## FastAPI 测试接口

重启 AI 服务后在 `http://127.0.0.1:8002/docs` 的“客服场景测试”分组查看：

| 接口 | 用途 |
| --- | --- |
| `GET /internal/v1/tests/cases` | 返回20题和每题检查标准，不调用模型 |
| `POST /internal/v1/tests/run` | 执行一题，示例请求 `{"case_id":"01"}` |

两个接口都需要 `X-Internal-Service-Token`；执行接口还需要 `Authorization: Bearer <客户JWT>`。脚本从当前配置读取内部令牌，并通过 Ecommerce 演示登录接口取得客户 JWT，不需要手工粘贴密钥。

每题创建独立 AgentRun 和会话编号，不向实际聊天发布消息。页面决策读取后取消，不自动确认，不执行订单取消、扣分或退款。

## 检查通过的含义

检查包括：运行完成、回复非空、回复类型符合预期、工具无网络或契约错误、预期工具及参数正确，并且成功工具被通过校验的专家结论引用。售后问题只允许 `AFTER_SALE_NOT_FOUND` 作为预期失败，权限错误等不能冒充正常结果。

这些属于可自动核对的链路和路由检查，不能替代人工评判回复是否完整、自然或满足用户意图。HTTP 200、工具 HTTP 成功、模型能回复都不单独代表测试通过。

## OpenRouter 配置

当前沿用 `ChatOpenAI` 的兼容接口，无须更换 SDK：

```dotenv
LLM_PROVIDER=openai_compatible
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_MODEL=z-ai/glm-5.3-flash
LLM_API_KEY=你的OpenRouterKey
```

普通回复和强制 Function Calling 已实际调用通过。仅改 `.env` 后需要重启 AI 服务；SDK 连通不等于完整多智能体问答已通过，后者以测试报告为准。OpenRouter 兼容调用见[官方说明](https://openrouter.ai/developers)。
